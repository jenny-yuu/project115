檢索增強生成大型語言模型應用於：
台鐵東部幹線車站災害營運影響推估與應變指引App

摘要
臺灣東部地區地形狹長且地質敏感，聯外交通因缺乏替代性而高度倚賴台鐵東部幹線。近年頻繁受地震、颱風與豪雨影響，導致列車誤點與停駛事件屢見不鮮。現有交通與災害資訊高度分散，台鐵官方雖提供列車動態，但缺乏環境背景；氣象與地震資訊雖可由中央氣象署取得，卻難以直接對應至特定車站。災害發生當下，旅客需在多平台間反覆比對，才能夠了解整體情況，難以針對單一地點迅速形成完整的風險判斷與應變行動。

因此本計畫旨在開發以「東部幹線車站」使用者為核心視角的整合型 App，整合列車營運、災害監測與決策支援資訊，主要功能：
車站營運與環境整合監測：以單一車站為核心，即時整合列車誤點、停駛狀態及周邊氣候資訊，並以燈號方式呈現車站營運健康度。 
即時災害示警：針對車站所在地震度與豪雨警戒提供即時示警。
災害衝擊與停駛回復時間推估：
建構結合大型語言模型（Large Language Model, LLM）與檢索增強生成（Retrieval-Augmented Generation, RAG）之推論引擎，透過歷史營運案例建立向量檢索機制，比對即時災害監測資料與歷史情境，以相似度檢索推估營運影響程度與列車停駛預期營運回復時間區間，作為行程調整之時間參考依據。
情境式應變建議與主動推播：
整合交通部運輸資料流通服務平臺（Transport Data eXchange, TDX） [1]、中央氣象署 [2] 與地震測報中心 [3] 等多源異質資料。當系統偵測到使用者關注的車站或路段具停駛風險時，主動推播警示通知，並驅動LLM-RAG引擎綜整相關資訊，提供具體替代行程規劃與應變建議。

關鍵詞：台鐵東部幹線、災害復原預測、情境式應變建議、檢索增強生成、大型語言模型

研究動機與研究問題
研究動機：
東部交通高度依賴鐵路系統：
臺灣東部廊帶（臺北—宜蘭—花蓮—臺東）受限狹長地形與地理阻隔，對外交通聯繫高度依賴「台鐵東部幹線」。據 2023年統計，東部幹線年運量逾 820萬人次，約為民航運量的 34倍 [4]，顯示其於通勤、就學與觀光層面的不可取代性。然而，花東航線班次有限且成本高昂，長途客運的運能不足，蘇花公路亦常因地形風險而封閉，使東部在台鐵營運中斷時，極易陷入「交通孤島」困境。
複合型災害頻仍，營運不確定性升高：
近年氣候變遷與地質活動加劇東部交通系統之不確定性。以 2025 年為例，東部地區多次因短時強降雨引發土石流與堰塞湖溢流（如花蓮馬太鞍溪流域），造成鐵路設施受損停駛兩日 [5]；同年亦受鳳凰颱風 [6] 影響，強風豪雨導致部分區段預防性停駛或班次調整。此外，花蓮地區12月發生中規模地震後，台鐵依規定進行路線安全檢查與限速，進而造成列車延誤 [7]。人為意外亦可能干擾列車營運，使東部交通逐漸由單一災害事件，轉變為高頻率發生的「複合型災害」。
即時資訊分散，缺乏以「車站」為核心的風險整合視角：
對鐵路使用者而言，當地震、颱風或豪雨等災害導致鐵路營運中斷時，最大困境在於資訊分散且難以直接轉化為行動判斷。災害發生當下，旅客需分別查詢列車動態、氣象資訊與災害警戒，各平台資訊尺度不一，缺乏以「特定車站」為單位的整合呈現。此外現有系統多僅提供事實性數據，未能回應旅客最關心的問題，例如是否應改道或需等待的時間，使用者在高壓情境下難以迅速做出決策。
因此，本計畫聚焦營運風險高且交通替代性不足之台鐵東部幹線車站，整合歷史災害經驗與即時監測資料，建構以單一站點為核心的風險提示機制，以回應資訊分散問題，並提升旅客於災害情境下的即時決策能力。
研究問題：
本計畫擬探討問題如下：
異質資料的語義轉化與規則建立：如何針對不同空間尺度、型態與來源之原始數據，建立具體的「語義映射規則」，將其轉化為一致的結構化特徵，作為後續相似度計算與模型推論之基礎。
歷史案例的向量化建模與檢索邏輯：如何將前述經語義轉化後的結構化特徵，利用嵌入模型映射至高維度向量空間，並確立即時監測數據與歷史案例間的「相似度比對邏輯」，以精確檢索具參考價值的過往案例。
災害復原預測的生成與決策支援：結合檢索所得之歷史案例與即時監測數據，透過受限生成策略與提示工程，引導LLM產出具備實證基礎的「營運回復時間區間」與應變建議。
繁體中文與在地化模型之適用性探討：考量台鐵營運規章與專有名詞之特殊性，探討針對繁體中文優化之模型，相較於通用模型在理解台灣在地用語與生成決策建議上，是否具備更佳的效能與準確性。

3-2關鍵技術探討
計畫核心兩大面向「多源異質資料整合」與「大型語言模型輔助決策」。
前者解決資料來源分散、尺度不一致與即時性差異問題；後者則嘗試將複雜的即時災害與營運資訊，建立規則轉化為具決策意義的風險與時間預期指引。
3-2-1多源異質資料整合
ETL資料整合流程
資料整合（Data Integration）是將不同來源數據轉化為決策資訊的基礎。本計畫透過 ETL（Extract Transform Load, ETL）流程，針對交通部 TDX（列車即時動態）、中央氣象署（雨量、震度觀測）以及歷史災害營運紀錄資料進行自動化介接與清洗，其概念流程如圖一所示。

圖一、ETL（Extract, Transform, Load）流程
ETL 流程包含三個主要階段：
萃取（Extract）：自 TDX API 與氣象開放平台擷取原始 JSON資料。
轉換（Transform）：統一時間格式與座標系統，並處理空間尺度差異。
載入（Load）：結構化數據存入本地資料庫，以利後續 RAG 檢索。

地理空間映射（Geospatial Mapping）
地理空間映射為本計畫關鍵技術之一。透過將具空間屬性資料（如雨量、地震測站）依座標距離，精確映射至「特定車站」地理基準，解決不同資料在空間尺度上無法對齊的問題，確保系統貼近該站點周邊真實災害情境。[12]

3-2-2 大型語言模型（LLM）與檢索增強生成（RAG）
大型語言模型（LLM）
大型語言模型（Large Language Model, LLM）本質為基於機率的生成模型，具備語意理解與自然語言生成能力，能進行「語意對語意（Semantic-to-Semantic）」的轉換與推論。透過大量文本資料訓練，模型能理解輸入文字的上下文脈絡，並預測最合理的後續文本序列。
依照取得方式，LLM 可概略分為「開放式」與「封閉式」兩類。開放式模型如 Hugging Face [13] 平台所提供之 LLaMA [14]，具備可自行部署、客製化調整與模型權重透明等優點，適合進行模型架構與訓練機制相關研究。近年亦出現多款強化繁體中文與台灣在地語料的開放模型，例如Taiwan-LLM [15]便是基於 LLaMA 架構所發展之在地化模型，透過持續預訓練（Continual Pre-training）方式，額外引入涵蓋台灣新聞、政府法規、公共政策與社群對話等高品質繁體中文語料，以補足通用模型於台灣語境下的語意落差，使其能更精確處理繁體中文語意結構、在地用語與公共運輸相關文本；後者如 OpenAI [16] 所提供之 GPT 系列模型 [17]，雖無法存取其內部權重，但於語意理解與生成品質上表現成熟，較適合應用導向與系統整合之研究情境。

檢索增強生成（RAG）
無論採用何種模型，若僅依賴模型內部之通用知識進行生成，仍可能受限訓練資料截止時間，或因缺乏特定領域知識產生事實幻覺（Hallucination），導致不可靠的推論結果 [18]。因此本計畫不採用純生成模式，而是結合檢索增強生成（RAG）技術，其核心關鍵在於「專用領域知識庫的建立」。先將台鐵歷史災害事件（震度、雨量）與對應的營運處置紀錄，透過嵌入模型（Embedding Model）轉化為高維度向量，建置專屬向量資料庫。即時災害發生時，系統運作流程如下：
檢索（Retrieval）： 將當下災害數據轉為向量，在資料庫中計算資料相似度，檢索出過往最相似的歷史案例。
增強（Augmentation）：檢索到歷史事實作提示詞（Prompt）背景知識。
生成（Generation）：限制 LLM 僅能依據上述檢索到的事實進行語意重組與推論，生成具備實證基礎的決策建議。

3-2-3 RAG 效能優化技術探討
混合檢索機制（Hybrid Search）：結合語意檢索與關鍵字檢索
單純的語意檢索（向量檢索）機制 [19] 雖可捕捉語意相似度，惟在面對專有名詞或規章關鍵字時，因對字面差異不夠敏感，進而影響檢索精確度。因此，成熟的 RAG 架構多採用混合檢索機制，結合關鍵字檢索（如 BM25）[20, 33, 34] 與語意檢索（Semantic Search），兼顧關鍵詞匹配與上下文語意理解，提升候選案例檢索的完整性與可靠性。確保抓到精確名詞同時也能理解上下文語境。

生成策略探討：受限生成與引導生成
受限生成（Constrained Generation）強制模型遵循特定輸出格式（如 JSON），確保生成內容具備結構化與規範性，適用產出如「回復時間區間」等需高度一致性且具可解釋性之結果。而引導生成（Guided Generation）[21] 則是透過提示工程（Prompt Engineering）[22] 或上下文脈絡，引導模型聚焦於計畫核心「營運影響判斷」與給予使用者「行動建議」，避免生成發散或無關敘述。

語意向量表示與嵌入模型（Embedding Model）應用
隨著歷史資料庫持續累積，單純線性向量掃描（Linear Scan）已無法滿足災時即時應變需求。因此需透過嵌入模型技術 [23, 24, 35]，將非結構化文本轉為高維度語意向量 [37]。目前針對繁體中文語境優化之嵌入模型，如 BGE-M3（BAAI General Embedding）與 OpenAI 所提供之 text-embedding-3 [25] 系列模型，具備較佳語意捕捉能力，能有效處理台鐵營運規章、災害通報與歷史處置紀錄中專有名詞與長文本，降低通用模型於繁體中文情境可能產生的語意偏差。

Extract（萃取）：透過 API 定期擷取交通部 TDX、中央氣象署與相關政府資料平台之原始資料。

4-2 LLM－RAG 模型設計：規則式語義映射與兩階段檢索
本計畫之核心目標，是在特定車站發生災害時，以「過去類似情境」作為參考，並提供可行的行程與應變提示。因此採用結合「規則式語義映射」與「檢索增強生成（RAG）」之推論架構，以確保結果具備可解釋性。

災害資料語義化（規則映射）
相似歷史案例檢索（向量比對）

預期結果

圖五、預期結果（主要畫面）
車站層級營運與環境資訊整合（主要畫面）於車站資訊頁面中，系統依停駛或延誤狀態呈現特定車站之即時營運資訊，並同步顯示相關氣象與災害監測資料，提供以單一站點為核心之風險判斷視角，並根據營運狀態與歷史案例提供應變建議。


圖六、預期結果（首頁、環境資訊詳述、推播設定頁）
列車營運總覽與異常車站呈現（首頁）系統可依北迴線、宜蘭線與台東線進行路線選擇，並於總覽頁面標示發生停駛或延誤之車站，使用者能快速掌握東部幹線整體營運狀況。
個人化通勤訂閱與主動推播機制
使用者可設定關注之通勤時段與路線，當系統偵測到相關車站發生營運異常或災害警示時，主動推播即時通知，提升使用者對突發事件之即時應變能力。
